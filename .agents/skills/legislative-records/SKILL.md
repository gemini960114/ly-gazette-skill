# 教文委員會公報紀錄查詢

## 資料位置（相對於專案根目錄）

| 用途 | 路徑 |
|---|---|
| 原始 .doc（大量圖片，**不要直接讀**） | `output/legislative_communiques/2026_DOC/DOC/` |
| 正規化 md（查詢的唯一依據） | `output/legislative_communiques/2026_MD/*.md` |
| 索引（腳本產生，**不要手改**） | `output/legislative_communiques/2026_INDEX/` |

索引檔：

- `2026_INDEX/meetings.md`：所有檔案一覽，包括日期、會議別、主席、議程摘要、段落數、字數、代碼、備註（圖片、續頁）
- `2026_INDEX/meetings/<代碼>.md`：單場明細，包括議程、答詢官員、**發言段落表**（類型｜發言者｜時間｜行號｜字數｜答詢者｜開頭摘錄）、決議／決定
- `2026_INDEX/legislators.md`：委員一覽（依發言總字數排序）→ `2026_INDEX/legislators/<姓名>.md`：該委員每一段發言
- `2026_INDEX/speakers.md`：官員和公聽會學者專家，記錄在哪些會議發言、首次發言行號
- `2026_INDEX/segments.json`：機器可讀版，給 search.py 用

**代碼**是檔名中 `LCIDC01_` 之後的部分，例如 `1156401_00003`，用來對應 md 檔：`2026_MD/*_<代碼>.md`。

## 查詢流程

**一律先查索引，再用行號讀原文。** 單份 md 可能超過 40 萬字，不要整份 Read。

1. **問某位委員** → 讀 `2026_INDEX/legislators/<姓名>.md`，挑出相關段落（看日期、答詢者、摘錄），再讀原文。
2. **問某位官員或專家** → 在 `2026_INDEX/speakers.md` 用 Grep 找姓名，得到會議代碼和行號。
3. **問某場會議** → 在 `2026_INDEX/meetings.md` 找代碼 → 讀 `2026_INDEX/meetings/<代碼>.md`。
4. **問議題或關鍵字** → 用搜尋腳本：
   ```
   uv run python .agents/skills/legislative-records/scripts/search.py 關鍵字 [關鍵字…] [--speaker 姓名] [--owner 委員] [--date 2026-07] [--kind 全體|聯席|公聽會] [--any]
   ```
   結果會依「會議 → 發言段落」分組，標出命中行是誰說的、屬於哪位委員的段落、答詢者是誰。
   - 多個關鍵字預設要在**同一行**同時出現（AND）；加 `--any` 改成 OR。同義詞要分開查，或用 `--any` 一起查，例如 `食安 致癌油 食品安全 --any`。
   - `--speaker` 篩「這句話是誰說的」，`--owner` 篩「在哪位委員的質詢段落裡」，例如官員回答某委員的話就用 `--owner`。
   - 結果被截斷時，用 `--date`、`--owner` 縮小範圍，不要只看前幾筆就下結論。
5. **讀原文**：
   ```
   uv run python .agents/skills/legislative-records/scripts/search.py --show <代碼>:<起>-<迄>
   ```
   也可以直接用 Read，offset 設為起始行號，因為索引的行號就是 md 檔的實際行號。
6. **跨場次彙整**（例如某委員對某議題的立場、部長在不同場次的說法）→ 用 4 找出所有段落，**逐段讀原文**後再彙整。不要只根據索引摘錄下結論，因為摘錄只是段落開頭。

## 回答規則

- 每個論點都附出處，格式為 `[日期 會議別 L行號](output/legislative_communiques/2026_MD/<檔名>.md#L<行號>)`。
- 區分**委員的提問或主張**和**官員的答覆或承諾**。官員說「會研議」「會檢討」「回去了解」時要照原話引用，不要寫成「已承諾」或「同意」。
- 只根據原文回答。查不到就說「目前收錄的紀錄中沒有找到」，並說明查了哪些關鍵字和範圍，不要用一般知識補充。
- 引用原話用「」並保留原文；摘要要明確標示是摘要。

## 原文格式

- **發言者標籤**是「姓＋職稱＋名：」：`郭委員昱晴：`＝郭昱晴委員，`李部長遠：`＝李遠部長，`張廖次長萬堅：`＝張廖萬堅次長，`高金委員素梅：`＝高金素梅（複姓）。索引和 search.py 已經把標籤換成姓名，直接用全名查詢即可。用 Grep 搜原文時，要改用標籤格式。
- **主席**只標 `主席：`，實際是誰要看該場明細的「主席」欄（每場不同，常由委員擔任）。
- 委員質詢開頭**有時**帶時間，例如 `葛委員如鈞：（9時16分）`，但很多沒有。段落是以「發言的委員換人」切分的。
- **段落類型**：`委員`（質詢或逐條審查發言，字數 < 200 的多半是插話或程序發言）、`報告`（官員專題報告）、`書面質詢`、`書面資料`（機關書面報告，不是現場發言）、`發言`（公聽會的學者專家或機關代表）。
- 全體會議開頭常夾著**上次會議的議事錄**，裡面的決議屬於上一場，明細的「決議／決定」已經排除這部分。
- 原文偶爾有錯字，例如 `吳委員憶沛`（已在索引中合併為吳沛憶）、第20次的文化部報告被標成「教育部書面資料」。引用時照原文，必要時加註。

## 已知資料限制

- **檔名的次別不可靠，以檔內標題為準**（索引的「會議」欄已經校正）。例如檔名寫「第22次」的 `1156701_00004` 實際是第23次；檔名寫「第1次」的 `1157501_00004`、`_00005`、`_00006` 分別是聯席第1次、全體第27次、第27次續頁。
- **同一場會議可能分成好幾個檔案**，例如多日會議（第10次、第18次）或續頁。沒有標題的檔案是同一天前一份的續頁，索引標為「（續）」。
- **有 8 份主要是掃描圖片**，`meetings.md` 備註標「⚠主要為圖片」。內容是預算提案表（凍結、刪減及理由）、法案條文對照表等，**沒有文字可以查**，也不做 OCR。使用者問到預算提案或條文對照時，要明確告知這部分只能看原始 .doc，並指出是哪幾份。其他檔案的「含 N 張圖片附件」也是同樣情形。
- 範圍只限 `2026_DOC/DOC/` 收錄的檔案，時間範圍見 `meetings.md`。

## 新增資料後更新

使用者說「加了新公報」「重新整理」時，在專案根目錄依序執行：

```
uv run python .agents/skills/legislative-records/scripts/extract_doc_md.py   # .doc → md（增量；需要 Windows + Word）
uv run python .agents/skills/legislative-records/scripts/build_index.py      # 重建全部索引
```

- 只收 **.doc / .docx**。使用者提供 PDF 時，請他到立法院公報系統改下載**同一份紀錄的 DOC 版**，因為 PDF 是雙欄排版，轉成文字容易錯亂。
- `*.doc.part` 是還沒下載完的檔案，會自動略過。
- 完成後回報新增了哪幾場會議（看 `meetings.md`），以及轉換時有沒有出現「⚠主要為圖片」的警告。
- Mac / Linux 沒有 Word：見 `extract_doc_md.py` 開頭說明，改用 LibreOffice 轉換（未實測）。
- 發現新的姓名錯字時，加到 `build_index.py` 的 `ALIASES` 後重建索引。
